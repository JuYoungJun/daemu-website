# 대무 (DAEMU) — 클라이언트 인계 안내서

> 본 문서는 대무(DAEMU) 웹사이트를 처음 받아보시는 분이
> **기술 배경 없이도 데모를 살펴보고, 운영 단계로 넘어갈 준비를 하실 수 있도록**
> 정리한 안내서입니다.
>
> 작성일: 2026-05-04

---

## 1. 지금 보고 계신 것은 무엇인가요?

**현재 사이트는 클라이언트 시연용 데모입니다.**

- 디자인, 메뉴 구조, 어드민 페이지, 메일 발송, 콘텐츠 관리 기능은 **실제 동작합니다**.
- 다만 정식 운영 인프라(도메인·서버·운영용 데이터베이스)는 아직 적용되지 않았으며,
  결정 후 본 개발자가 운영 환경으로 옮기는 단계가 별도로 있습니다.
- 데모는 시연을 위한 임시 환경이라, 입력하신 데이터는 운영 시작 시 새 환경으로 옮기지 않고 초기화됩니다.

쉽게 말씀드리면 — **지금 보시는 것은 "완성된 사이트의 시뮬레이션"** 이고,
정식 운영 사이트는 클라이언트 결정 사항이 정해진 뒤 옮겨 심어 드립니다.

---

## 2. 데모에 포함된 것

✅ **공개 페이지**
- 메인 / 회사 소개 / 작업 사례 / 팀 소개 등 모든 공개 페이지가 정상 동작합니다.
- 모바일·태블릿·PC 반응형 레이아웃이 적용되어 있습니다.
- 검색엔진(네이버·구글) 노출에 필요한 기본 메타 정보가 들어가 있습니다 (운영 도메인 적용 후 등록 완료).

✅ **어드민(관리자) 페이지**
- 로그인 후 콘텐츠·문의·파트너·작업·통계·미디어·메일·캠페인 등을 관리할 수 있습니다.
- 어드민 권한은 역할별로 분리되어 있습니다(슈퍼어드민 / 일반 어드민 / 모니터링 등).
- 2단계 인증(앱 OTP)을 등록할 수 있습니다.

✅ **문의 / 메일 기능**
- 공개 페이지의 문의 폼이 정상 동작합니다.
- 자동 메일 회신이 가능합니다 (발신 도메인은 운영 단계에서 클라이언트 도메인으로 변경).

---

## 3. 데모에 아직 포함되지 않은 것 (운영 단계에서 적용)

⏳ **운영 인프라**
- 클라이언트 전용 도메인(예: `daemu.kr`)
- HTTPS 인증서
- 운영 전용 서버
- 운영 전용 데이터베이스 + 자동 백업

⏳ **장기 보존이 필요한 것**
- 어드민에서 업로드한 이미지/파일은 데모 단계에서는 임시 저장됩니다 (재배포 시 초기화).
  운영 단계에서 영구 보관 스토리지로 이전됩니다.
- 데모 단계 동안 저장된 콘텐츠/문의/통계 데이터는 운영 시작 시 초기화됩니다.

⏳ **운영 보호 장치**
- 자동 모니터링 / 알림 / 사고 보고
- 분기별 보안 점검
- 시크릿(비밀번호·토큰) 정기 회전

이 항목들은 데모 단계에서 빠진 것이 아니라, **운영 시작 전에 적용되는 정상 절차**입니다.

---

## 4. 어드민 데모 계정 사용 안내

### 4.1 어드민 로그인 정보
- 본 개발자가 데모 시연 직전 안전한 임시 비밀번호를 설정해 별도로 전달드립니다.
- 임시 비밀번호는 **데모 시연 전용**입니다.
- 시연 후 폐기를 원하시면 본 개발자에게 알려주시면 됩니다.

### 4.2 데모 시연 중 권장 동작
- 화면 둘러보기 ✅
- 메뉴 구조 / 페이지 흐름 확인 ✅
- 가짜 콘텐츠로 글 등록 / 수정 / 삭제 시도 ✅
- 메일 발송 테스트 (테스트용 주소로) ✅

### 4.3 데모 시연 중 권장하지 않는 동작
다음은 **데모 단계에서는 입력하지 말아 주세요**:

❌ 실제 고객의 성명·전화번호·이메일
❌ 실제 결제·계약 정보
❌ 실제 직원의 사번·신분증 번호 등 식별 정보
❌ 비공개 사업 전략·가격표·거래처 정보

이유:
1. 데모용 데이터는 운영 시작 시 새 환경으로 옮기지 않고 초기화됩니다.
2. 데모 환경은 운영 등급의 데이터 보존·백업이 적용되지 않습니다.
3. 개인정보 보호법(PIPA) 관점에서, 데모 환경은 정식 처리방침이 아직 적용되어 있지 않습니다.

시연용 콘텐츠는 가공/예시 데이터로 입력해 주시면 됩니다.
실제 고객 데이터 이관은 **운영 시작 후** 안전한 절차로 진행됩니다.

## 5. 운영 단계로 가기 전에 결정해야 할 사항

다음 항목은 **클라이언트 결정 사항**입니다. 결정 후 본 개발자가 운영 단계 작업을 진행합니다.

### 5.1 도메인
- 사용하실 도메인(예: `daemu.kr`)을 결정·등록해 주세요.
- 이미 보유하신 도메인이 있으면 알려주세요.
- DNS 관리 권한도 함께 확인 부탁드립니다 (카페24 마이페이지, Cloudflare 등).

### 5.2 호스팅 / 서버
- 본 개발자는 **카페24 클라우드 서버 (월 ~9,900원, Ubuntu 22.04)** 를 권장합니다.
  - 이유: 비용 효율, 한국 트래픽 적합, 클라이언트 콘솔 접근 단순.
- 다른 호스팅 선호가 있으시면 알려주세요.
- 서버 비용은 클라이언트 부담이며, 카페24 계정으로 직접 결제 가능합니다.

### 5.3 데이터베이스
- 운영 데이터베이스는 다음 중 하나로 결정합니다:
  - **Aiven MySQL** (외부 매니지드, 자동 백업 강점)
  - **카페24 MySQL** (서버 동일 사업자, 단일 청구서)
  - 기타 옵션
- 결정 후 본 개발자가 연결·검증을 진행합니다.

### 5.4 어드민 사용자
- 운영 어드민 계정을 사용하실 분을 알려주세요 (이메일 + 이름 + 권한 수준).
- 데모 비밀번호는 폐기하고 운영용 새 비밀번호로 발급해 드립니다.
- 분기 1회 비밀번호 회전을 권장합니다.

### 5.5 최종 콘텐츠
- 데모에 들어 있는 텍스트·이미지는 시연용 임시 콘텐츠입니다.
- 운영 시작 전 클라이언트가 최종본을 어드민으로 입력해 주시거나,
  본 개발자가 전달받아 일괄 입력해 드릴 수 있습니다.

### 5.6 유지보수 책임 범위
- 운영 시작 후 콘텐츠 관리(글 작성·이미지 교체 등)는 클라이언트 측에서 어드민으로 직접 가능합니다.
- 시스템 운영(서버 관리·보안 패치·문제 대응 등)은 별도 협의입니다.
- 가능한 운영 모델:
  1. **클라이언트 직접 운영** — 본 개발자는 비상 사고 시에만 지원.
  2. **개발자 위탁 운영** — 정기 점검·패치·백업 점검을 본 개발자가 담당 (월/분기 협의).
  3. 혼합 — 콘텐츠는 클라이언트, 시스템은 개발자.
- 운영 시작 전 명확히 합의 후 시작합니다.

## 6. 간단 운영 가이드 (어드민 사용)

### 6.1 로그인
1. 본 개발자가 알려드린 어드민 URL 접속.
2. 이메일 + 비밀번호 입력.
3. (등록 시) 2단계 인증(OTP) 코드 입력.

### 6.2 자주 사용하는 메뉴
- **콘텐츠 관리** — 페이지 글 / 이미지 / 캠페인 등록·수정.
- **문의 관리** — 공개 폼으로 들어온 고객 문의 확인 및 회신.
- **작업/사례 관리** — 포트폴리오 사례 등록.
- **파트너 관리** — 협력사 목록 관리.
- **메일 보내기** — 공지·알림 메일 발송.
- **통계** — 트래픽·문의·캠페인 효과 확인.
- **설정** — 어드민 사용자·권한·2단계 인증 관리.

### 6.3 주의 사항
- 어드민 비밀번호는 **타인과 공유하지 마십시오**. 다른 사람이 운영해야 한다면 별도 어드민 계정을 발급합니다.
- 2단계 인증을 등록하시면 복구 코드를 안전한 곳에 보관해 주세요 (분실 시 본 개발자에게 복구 요청).
- 어드민 페이지에서 콘텐츠 삭제는 즉시 적용됩니다 — 백업이 없는 항목은 복구가 어려울 수 있습니다.

## 7. 운영 시작 전 체크리스트 (클라이언트 측)

운영 시작 전 다음을 본 개발자와 함께 점검합니다.

| # | 항목 | 클라이언트 확인 |
|---|---|---|
| 1 | 도메인 결정·등록 | ☐ |
| 2 | 호스팅(서버) 선택 | ☐ |
| 3 | 데이터베이스 선택 | ☐ |
| 4 | 어드민 계정 사용자 명단 + 이메일 | ☐ |
| 5 | 운영용 어드민 비밀번호 수령 채널 합의 (대면 / 1Password 등) | ☐ |
| 6 | 최종 콘텐츠 입력 방법 합의 | ☐ |
| 7 | 메일 발신 도메인 인증 절차 합의 | ☐ |
| 8 | 검색엔진 노출 여부 결정 (네이버·구글) | ☐ |
| 9 | 유지보수 책임 범위 합의 | ☐ |
| 10 | 사고 발생 시 연락 채널 합의 | ☐ |
| 11 | 데모 데이터 → 운영 데이터 초기화 일정 합의 | ☐ |
| 12 | 운영 가동 일자 합의 | ☐ |

본 체크리스트가 모두 체크되면 운영 단계로 전환합니다.

## 8. 유지보수 / 업데이트 기대치

운영 시작 후, 다음 작업은 정기적으로 진행됩니다 (책임 범위 협의에 따름):

| 작업 | 주기 | 담당 (예시) |
|---|---|---|
| 콘텐츠 관리 (글·이미지·메뉴) | 수시 | 클라이언트 |
| 어드민 비밀번호 회전 | 분기 1회 | 클라이언트 또는 개발자 |
| 보안 패치 점검 | 월 1회 | 개발자 |
| DB 백업 정상 작동 점검 | 월 1회 | 개발자 |
| TLS 인증서 자동 갱신 점검 | 분기 1회 | 개발자 |
| 트래픽 / 에러 모니터링 | 상시 | 개발자 |
| 신규 기능 / 디자인 변경 | 별도 협의 | — |

본 개발자가 위탁 운영을 맡는 경우 정기 보고서(월 1회)를 드릴 수 있습니다.

## 9. 사고 발생 시 안내

운영 중 사이트 접속 불가 / 어드민 로그인 안 됨 / 메일 미발송 등 사고가 발생하면:

1. 본 개발자에게 즉시 연락 (인계 시 받으신 연락처).
2. **사이트나 어드민에서 임의로 동일한 작업을 반복 시도하지 말아 주세요** — 상황 파악이 먼저입니다.
3. 본 개발자가 1차 진단 → 롤백 또는 핫픽스 → 결과 보고 순서로 진행합니다.
4. 사고 후 원인·재발 방지 보고서를 드립니다.

## 10. 자주 묻는 질문 (FAQ)

**Q1. 데모 단계인데 사이트가 느릴 때가 있어요.**
- 데모용 무료 백엔드는 15분 동안 사용이 없으면 자동 절전됩니다. 처음 접속 시 30~60초 정도 깨어나는 시간이 필요합니다. 운영 단계에서는 이 절전 모드 없이 항상 켜져 있습니다.

**Q2. 어드민에 올린 이미지가 사라졌어요.**
- 데모 단계의 이미지 저장소는 임시 환경입니다. 운영 단계에서는 영구 보관 스토리지로 이전됩니다.

**Q3. 데모 사이트 주소를 다른 분께 공유해도 되나요?**
- 가능하지만, **어드민 페이지 주소와 비밀번호는 공유하지 마세요**. 공개 페이지 주소만 공유 가능합니다.

**Q4. 검색엔진에 노출되나요?**
- 데모 단계에서는 검색엔진 등록을 보류합니다. 운영 도메인이 결정되면 네이버·구글 등록을 진행합니다.

**Q5. 모바일에서도 동작하나요?**
- 네. 공개 페이지·어드민 모두 모바일 반응형이 적용되어 있습니다.

**Q6. 어드민 비밀번호를 까먹었어요.**
- 본 개발자에게 알려 주시면 안전한 채널로 재발급해 드립니다. 어드민 페이지에서 직접 재설정 옵션도 추가 협의 가능합니다.

**Q7. 운영 단계로 넘어가면 데모 사이트는 어떻게 되나요?**
- 운영 도메인 적용 후 데모 URL 은 더 이상 사용하지 않으며, 데모 데이터는 폐기됩니다.

## 11. 마지막 한 줄

데모 단계의 한계는 **결함이 아니라 정상 절차**입니다.
운영 단계 결정 사항(§5)이 합의되는 대로, 안전하고 단계적으로 운영 환경을 준비해 드립니다.

문의: 본 개발자 연락처 (인계 시 별도 안내).
